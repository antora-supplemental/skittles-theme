== 2026-10-26

=== Per-build cache-busting of CSS and JS

* A phone still showed the blank gap above the content and the two-line breadcrumb at 2:11 AM CDT, after both fixes were live. Emulating a 320px Pixel with touch, DPR 3 and the dark scheme saved showed no gap on the live site. Putting back the old `.nav-container { position: relative }` rule reproduced the 600px gap exactly, so the phone was running stylesheets it had cached before the fix. They have fixed names and a 4-hour cache lifetime.
* The build now adds `?v=<content hash>` to every `_/css`, `_/js` and `search-index.js` URL in the generated HTML (`scripts/cache-bust.mjs`), so each deploy fetches fresh assets. HTML itself is cached for 10 minutes.
* `pnpm test:layout` now emulates phones (mobile user agent, touch, DPR 3, scheme saved in localStorage), adds a 320px width, and fails on horizontal overflow.

=== Valentus Layout 4.2.1, browser test for the content top

* Valentus Layout moves to v4.2.1: the breadcrumb scrolls sideways with no scrollbar and fades each edge whenever text is hidden past it.
* Reports of a blank gap above the content after the mobile fix came from cached CSS. The served stylesheets have unversioned URLs and are cached for up to 4 hours, so a browser kept the old `skittles-chrome.css`. A hard reload (Ctrl+F5) clears it.
* A new real-browser test (`pnpm test:layout`, run in the deploy workflow) checks where the article starts at widths from 360 to 1920px, light and dark, right after load and 2 seconds later, and fails on a gap or a scroll jump. Details: xref:changelog-details/history/2026-10-26 - content top browser test.adoc[].

=== Shared chassis placeholder logo, color-scheme 0.5

* The header placeholder logo and favicons now come from `@antora-supplemental/brand-placeholder` v0.1.0 (antora-ui-chassis). The bundle build bakes it in last and checks that no theme layer ships its own brand files. Valentus Layout moves to v4.2.0, whose header calls the shared `brand-logo` partial.
* The skittle mark stays on this demo site only; the shipped bundle has no Skittles logo.
* color-scheme moves to v0.5.3 and light-dark-mode to v0.1.3 (`color-scheme-tokens@0.5`).

=== Mobile content no longer starts below the fold

* Below 1024px the page content started under a blank screen-tall gap. The Skittles overlay set `.nav-container { position: relative }`, which pulled Valentus's hidden fixed nav drawer into the page flow. The rule is gone; a test now guards against it.
* xref:changelog-details/2026-10-26 - mobile content below the fold.adoc[Details]

== 2026-10-25

=== Initial Skittles theme v0.1.0

* Skittles Layout: a small overlay on Valentus Layout 4.1.0 adding rainbow strips at the top and bottom of the page, a rainbow nav/content divider, rainbow TOC wires, and 2px high-saturation control borders.
* Skittles Paint: 11 color schemes in one `@color-schemes` manifest stylesheet. There is a light and a dark scheme for each of Strawberry, Orange, Lemon, Green and Grape, plus Grape Soda, a bright purple scheme with no slot.
* Every light/dark scheme is only a slot candidate. Picking one fills that slot and leaves automatic light/dark switching on. Only Grape Soda (slot none) turns the automation off.
* Generated contrast: text meets 4.5:1 and UI boundaries meet 3:1 on every surface. axe-core reports 0 contrast violations over 5 pages and 11 schemes.
* The skittle header mark lives only in the docs brand overlay. The shipped bundles add no logo files.
* xref:changelog-details/2026-10-25 - initial skittles theme.adoc[Details]
